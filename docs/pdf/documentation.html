Summary

Radios that share one frequency take turns in time slots. Two radios must not share a slot if they are neighbours, or if they have a neighbour in common (the hidden terminal). I model those pairs as the square of the radio graph, G², so a collision-free schedule is exactly a proper colouring of G², with one colour per time slot.

  • Part 1. A Python CLI builds the radio graph from coordinates (500 m range), builds G², and colours it with a portfolio of heuristics led by DSATUR. It then proves how good the result is: a lower bound from the largest group of mutually conflicting radios, plus a bounded exact search when needed. An independent validator re-checks every schedule before anything is printed.
  • Final value, assessment grid: 9 slots, proven optimal, because 9 radios (Node_06 and its 8 neighbours) all conflict with each other. On an irregular 16-radio layout the same code reaches 4 slots, so every slot is reused by 4 radios.
  • Part 2. The schedule drives a 16-radio EMANE 1.5.2 TDMA network in one Docker container. Before each run the Brain predicts, for every link, whether a frame will get through. EMANE matched 396 of 396 predictions at 2–4 ms slots. The optimized schedule caused zero collisions in every run. A deliberately wrong control schedule (2-hop rule ignored) lost 97–99% of frames on exactly the links predicted.
  • One honest limit. At the required 1 ms slots, the 2-vCPU test machine could not emulate 16 radios in real time, so some frames arrived after their slot ended. These were timing drops, never collisions; at 2 ms and 4 ms delivery was 98.7% and 99.7%.

Understanding the problem

Collisions happen at the receiver

In TDMA every radio gets an exclusive slot in a repeating frame. A collision is a receiver event: if two signals reach the same radio in the same slot, it decodes neither. That gives three cases:

From rules to a graph

G (communication graph): one node per radio, an edge when the Euclidean distance is ≤ 500 m (inclusive). H = G² (conflict graph): an edge between two radios whose hop distance in G is 1 or 2. Those are precisely the pairs that must not share a slot.

Key insight. A valid TDMA schedule is a proper vertex colouring of G². The minimum frame length is the chromatic number χ(G²). Colouring G alone is not enough: in A–B–C, A and C are not adjacent in G, so they may get the same colour and collide at B.

Design process: how the solution was reasoned out

Each step below is a question I had to answer, the decision taken, and why. The order is the order in which the work was done.

  1. What exactly causes a collision? → A receiver hearing two transmissions. → So the rule is "no shared slot within 2 hops", which is exactly G². This turns a radio problem into a well-studied graph problem.
  2. Can the minimum be found exactly? → Minimum graph colouring is NP-hard in general, so no fast algorithm is known for every network. → Use fast heuristics, but do not just claim quality: measure it against a lower bound.
  3. Which heuristic? → DSATUR was required as the baseline; I did not assume it is best. → I measured it against five other greedy orders, 100 seeded random orders and an iterated-greedy refinement on 290 random networks, and kept the best valid result. Ties keep DSATUR's answer, so extra attempts can never make the result worse.
  4. How do I know the answer is good? → A clique (radios that all conflict pairwise) needs one slot per member, so its size is a hard minimum. → If the heuristic reaches it, the schedule is proven optimal. If not, a bounded branch-and-bound search proves or improves it, and otherwise the report says "best found".
  5. How do I know the code is correct? → An independent validator recomputes 1- and 2-hop pairs by breadth-first search on G, without trusting G². The pipeline refuses to print an unverified schedule. 102 tests cover the 18 required cases and more, and deliberately injected bugs check that the tests catch real faults.
  6. Does it hold up on a real emulator? → The Brain writes a full EMANE scenario and predicts each link's outcome before the run. A wrong "control" schedule runs alongside, proving the emulator would catch a bad schedule.
  7. What did I learn along the way? → (a) For the assessment's own example grid, 9 slots is a proven minimum, so the 5-slot sample output in the brief cannot be collision-free (§5.2). (b) EMANE at 1 ms slots needs CPU headroom; slot length separates emulator timing from schedule correctness (§6.5).

Colouring algorithm

Greedy colouring visits radios in some order and gives each the lowest slot not used by an already-coloured conflicting radio. It is always valid. Its quality depends only on the visiting order, so the method is about choosing good orders:

AttemptOrder ruleWhy it is in the portfolio
DSATUR (baseline)Next = radio whose neighbours already use the most distinct slotsHandles the most constrained radio first; strong and standard
largest_firstMost neighbours first (Welsh–Powell)Places hubs early
smallest_lastPeel least-connected radios, colour in reverseStrong on sparse geometric graphs
independent_set, BFS, DFSStructural ordersDiversity: different failure modes
random order ×100Seeded random permutations (random.Random(42))Escapes blind spots of fixed rules; reproducible
iterated greedyRe-colour keeping each slot's radios togetherCan never use more slots, often fewer

Proving optimality

A clique in G² is a set of radios that all conflict pairwise, so each needs its own slot. Its size ω is therefore a lower bound: χ(G²) ≥ ω. In G² every radio together with all its neighbours forms a clique, so ω ≥ (max degree + 1). The maximum clique is found exactly (Bron–Kerbosch). If the heuristic uses ω slots, the schedule is proven optimal and the clique is the certificate. If a gap remains, a bounded branch-and-bound search (DSATUR order, clique pre-coloured to break symmetry, 200,000-node budget) either finds a better schedule, proves the current one optimal, or stops and labels the result "best found". Example: 7 radios on a ring give ω = 3, yet every heuristic needs 4. The search proves 4 is optimal in 4 search nodes.

Correctness safeguards

  • Independent validator: recomputes all pairs within 2 hops by breadth-first search on G. A bug in building G² cannot validate itself.
  • Validation gate: the pipeline raises ScheduleValidationError (exit code 3) rather than return an invalid schedule. A test injects a broken optimiser to prove this.
  • Determinism: natural node order (Node_2 before Node_10) and one seeded generator, so the same input and seed give byte-identical output.

A note on the 5-slot sample output in the brief

The brief's sample shows 5 slots for these coordinates. Figure 3 proves at least 9 are needed. The sample also gives Node_01 and Node_03 the same slot although both neighbour Node_02, a hidden-terminal collision. I read the sample as an illustration of the output format. My validator rejects that assignment (a test shows which pairs collide), and Part 2 shows a 4-slot schedule of the same kind losing packets in EMANE.

Part 2: EMANE integration and results

What EMANE does, in plain words

EMANE emulates radios in real time. Each radio is an NEM: an emane process with a virtual network interface (emane1…emane16), a MAC layer and a PHY layer. A frame written into emane5 is queued by NEM 5's MAC, sent over an emulated channel, and judged by every other NEM's PHY (signal strength, noise, overlap). If accepted, it comes out of their interface. EMANE's TDMA radio model lets a radio transmit only in its scheduled slots and receive in the others, so EMANE is the right tool to test whether the schedule works on packets.

Experiment design

Prediction (computed before each run): a frame on link u → v is delivered if and only if v is not transmitting in u's slot, and no other neighbour of v transmits in u's slot. A link matches when predicted-delivered links measure ≥ 90% delivery and predicted-lost links ≤ 10%. Two schedules run through the same emulator:

  • optimized: the Part 1 schedule (9 slots on the grid). Predicts every link delivered.
  • G-only control: DSATUR on G instead of G² (4 slots, like the brief's sample). Predicts 64 of 84 directed links lost. Its job is to prove the emulator would catch a bad schedule.

What the results show

  1. EMANE enforces the schedule exactly as predicted. At 2 and 4 ms, 396 of 396 directed-link predictions matched (both schedules, both topologies). No frame ever crossed between radios out of range.
  2. The distance-2 schedule is collision-free on real packets. Zero collision drops in all 5 optimized runs, including at 1 ms.
  3. The 2-hop rule is necessary. The G-only control lost 97–99% of frames on exactly the predicted hidden-terminal links, with over 12,000 collision drops on the grid.

The 1 ms finding

At 1 ms, many frames in both schedules arrived after their slot had ended. 16 real-time EMANE processes on a 2-vCPU machine could not process every frame within 1 ms. That this is emulator timing, not the schedule, is shown by the data: for the same schedule, late drops fall from 3,408 to 221 to 45 frames as the slot grows from 1 to 2 to 4 ms, while collisions stay at 0. A host with more cores should close the gap at 1 ms; I have not measured that yet (§9).
